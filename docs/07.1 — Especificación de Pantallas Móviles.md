## 1. Introducción

Este documento especifica cada pantalla de la aplicación móvil de QuickBite: qué secciones contiene, qué muestra cada sección, qué acciones ofrece, qué estados puede tener y a dónde lleva cada acción. El objetivo es que cualquier desarrollador o agente pueda construir cada pantalla sin ambigüedad.

La arquitectura, la gestión de estado, la capa de servicios y la navegación residen en el documento 07. El sistema de diseño y los componentes visuales residen en el documento 09. Las decisiones canónicas (polling, pagos simulados, historial de búsquedas local, etc.) residen en el documento 05. Este documento no repite ninguno de esos contenidos.

---

## 2. Convenciones

### 2.1. Marcas de audiencia

Cada pantalla indica a qué perfil aplica:

| Marca | Significado |
| :--- | :--- |
| **Cliente** | Solo visible para el rol cliente |
| **Repartidor** | Solo visible para el rol repartidor |
| **Ambos** | Compartida entre cliente y repartidor (con posibles variaciones menores) |

### 2.2. Estructura de cada ficha

Cada pantalla se documenta con:

- Identificador único.
- Nombre.
- Ruta.
- Audiencia.
- Propósito.
- Secciones (con contenido y acciones).
- Estados (vacío, carga, error, éxito).
- Navegación de salida.
- Endpoints consumidos.
- Decisiones aplicables.

### 2.3. Codificación de pantallas

| Prefijo | Categoría |
| :--- | :--- |
| SCR-AUTH | Autenticación |
| SCR-CAT | Catálogo |
| SCR-CART | Carrito |
| SCR-ORDER | Pedidos |
| SCR-PROF | Perfil y ajustes |
| SCR-NOTIF | Notificaciones |
| SCR-DEL | Repartidor |
| SCR-COM | Transversales (errores, sin conexión) |
