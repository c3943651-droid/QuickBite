# QuickBite — Especificación: Gestión de Usuarios (Módulo 08.2)

> Fuente de verdad del módulo **Gestión de Usuarios** (staff/clientes) en el Panel Admin y su API.
> Numeración: completa la familia `08.x` (pages del panel). Reemplaza parcialmente la sección 12 de `08.1` en lo referente a usuarios.

## 1. Objetivo

Permitir que un administrador liste, consulte, cambie el rol y active/desactive cuentas de usuario
(clientes, administradores y repartidores) desde el panel admin. Cierre del hueco dejado por
`docs/08 — Panel Admin` donde no existía una pantalla de usuarios.

- **Usuarios consumidores:** administradores del restaurante.
- **Entidad gestionada:** `User` (del Domain, con sus roles `Cliente | Administrador | Repartidor`).

**Fuera de alcance:** creación de usuarios, edición de datos personales, registro de clientes,
gestión de contraseñas, gestión de repartidores como equipo (`/admin/delivery-persons` sigue siendo
el dueño del alta/vehículo/disponibilidad), ni gestión de auditoría (`AdminAudit`).

## 2. Supuestos

1. No existe cliente generado a medida para el panel; se usa el autoservicio `/users/profile` existente + estos endpoints nuevos.
2. "Desactivar" = `User.Activo = false` + revocación de refresh tokens activos (mismo mecanismo que `/users/sessions`). El JWT ya emitido expira por sí solo.
3. Cambiar el rol de un usuario registrado como repartidor (`DeliveryPerson` activo) se bloquea con `BusinessRuleException` para no romper el vínculo: se gestiona desde `/admin/delivery-persons`.
4. Un administrador no puede cambiar el rol ni desactivar **su propia cuenta** (regla de seguridad, respaldada en el servicio y en la UI).
5. El listado es paginado en servidor (mismo contrato `PagedResponse<T>` del catálogo).

## 4. Estructura del código

- **Domain** (`QuickBite.Domain`): `IUserRepository` → nuevo `GetPagedAsync(search, rol, activo, page, limit)`.
- **Infrastructure** (`QuickBite.Infrastructure`): `UserRepository.GetPagedAsync` (EF Core, `AsNoTracking`, `Include(Repartidor)`).
- **Application** (`QuickBite.Application/Admin`): `IAdminUserService` + `AdminUserService`, DTOs en `Admin/Dtos/AdminUserDtos.cs`, excepciones tipadas (`ValidationException`, `NotFoundException`, `ForbiddenException`, `BusinessRuleException`).
- **Api** (`QuickBite.Api/Controllers/Admin`): `AdminUserController` con `[Authorize(Roles = Roles.Administrador)]`.
- **Admin (Vite)**:
  - `lib/api/admin/users.ts` — hooks React Query (list/detail/updateRole/updateStatus) + mapas de rol/estado.
  - `app/users/page.tsx` — lista con buscador, filtros (rol, estado) y `DataTable`.
  - `components/features/users/user-detail-dialog.tsx` — detalle + cambio de rol + toggle de estado.
  - `components/layout/app-sidebar.tsx` — ítem "Usuarios" en sección **General**.
  - `app/main.tsx` (router) — ruta `/users`.

## 5. Estilo de código

- Backend: services con `IUnitOfWork`, Result vía excepciones tipadas de dominio, DTOs en `record`, propiedades x-form. **Zero lógica en controladores.**
- Frontend: React Query (claves en `lib/api/query-keys.ts`), mutaciones con `invalidateQueries`, `toast` de `sonner`, `getApiErrorMessage`, tablas con `DataTable` + `StatusChip`, diálogos Radix (patrón `product-detail-dialog.tsx`), máscaras/badges con los mapas locales.

## 6. Estrategia de pruebas

- **Unitarias** (`backend/tests/QuickBite.Tests.Unit/Application/AdminUserServiceTests.cs`): filtros del listado, `NotFoundException` en get/update, `ForbiddenException` en auto-cambio (rol y status), validación de rol inválido, bloqueo a repartidor vinculado, revocación de sesiones al desactivar, no-revocación al reactivar.
- **Integración** (`backend/tests/QuickBite.Tests.Integration/Persistence/UserRepositoryPersistenceTests.cs`): `GetPagedAsync` contra PostgreSQL (fixture `PostgresDatabaseFixture`), se omite sin BD.
- **Frontend**: vitest para `lib/api/admin/users.ts` (mapas de rol/estado) si aplica; el resto cubierto por `npm run build` (typecheck) y CI.

## 7. Contrato de API

Base `/api/v1/admin/users` — `Authorization: Bearer` (rol `administrador`).

| Método | Ruta | Descripción | Query/Body |
| :--- | :--- | :--- | :--- |
| GET | `/api/v1/admin/users` | Listado paginado con filtros | `search`, `rol` (opcional), `activo` (bool opcional), `page=1`, `limit=10` |
| GET | `/api/v1/admin/users/{id}` | Detalle del usuario | — |
| PUT | `/api/v1/admin/users/{id}/role` | Cambiar rol | `{ "rol": "cliente" \| "administrador" \| "repartidor" }` |
| PUT | `/api/v1/admin/users/{id}/status` | Activar/desactivar | `{ "activo": true \| false }` (revoca sesiones al desactivar) |

Seguridad: `PUT role/status` sobre la propia cuenta → `403 Forbidden`. Usuario inexistente → `404`.
Rol inválido → `422 Validation`. Repartidor vinculado a `DeliveryPerson` → `409 Conflict`.

## 8. Límites

- **Siempre:** tests antes de commit, `dotnet build -warnaserror`, cero lógica de negocio en controladores/pantallas.
- **Preguntar primero:** cambios al contrato de API, migraciones de BD, tocar el fixture de integración en modo producción.
- **Nunca:** exponer `PasswordHash`/tokens, cometer secretos, romper el contrato de `/users/profile` u otros endpoints existentes.

## 9. Páginas del panel

### ADM-USR-01 — Lista de usuarios

| Aspecto | Definición |
| :--- | :--- |
| Ruta | /users |
| Propósito | Listar y filtrar cuentas de usuario |

**Secciones:**

| Sección | Contenido | Acciones |
| :--- | :--- | :--- |
| Encabezado | Título "Usuarios", contador total | — |
| Barra de filtros | Búsqueda por nombre/email/teléfono, selector de rol (todos/cliente/administrador/repartidor), selector de estado (todos/activos/inactivos) | Filtrar |
| Tabla | Columnas: usuario (avatar+nombre+email), teléfono, rol (badge), estado (Activo/Inactivo), último acceso, acciones | Ordenar |
| Acciones por fila | Ver detalle, cambiar rol/estado (atajos) | Ejecutar |
| Paginación | Controles de la `DataTable` | Navegar |

**Estados:** cargando (skeletons), con datos, sin resultados, error con reintento.

**Navegación de salida:** Detalle.

**Endpoints:** GET /admin/users.

### ADM-USR-02 — Detalle de usuario

| Aspecto | Definición |
| :--- | :--- |
| Ruta | Modal desde la lista |
| Propósito | Consultar perfil, cambiar rol y activar/desactivar |

**Secciones:**

| Sección | Contenido | Acciones |
| :--- | :--- | :--- |
| Encabezado | Nombre, email, badge de estado | Cerrar |
| Datos del perfil | Teléfono, rol, fecha de alta, último acceso, intentos fallidos, bloqueado-hasta, reseña de repartidor (vehículo/entregas si aplica) | — |
| Cambio de rol | Select de rol (cliente/administrador/repartidor) | Cambiar |
| Toggle de estado | Switch Activo/Inactivo con confirmación previa si es desactivación | Activar/Desactivar |

**Reglas:** los controles quedan deshabilitados cuando el usuario es la cuenta actual del admin; el
servicio vuelve a protegerlo (403).

**Navegación de salida:** Lista.

**Endpoints:** GET /admin/users/{id}, PUT /admin/users/{id}/role, PUT /admin/users/{id}/status.
